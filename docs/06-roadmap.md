## Phase 0 · 准备（约 2 周）

**目标**：在写任何产品代码前，先验证关键技术假设成立，并厘清法律边界。

| # | 关键任务 | 验收标准 |
|---|---|---|
| 0.1 | D1 FTS5 trigram 可行性实测 | 将 3 个已发布语料全文入库，实测中文、中英混排、罗马字三类查询的召回与延迟；结论写入文档 |
| 0.2 | Pagefind 真实语料召回实验 | 用 866 篇文章实测；确认能否正确切分三语混排、是否需要前处理 |
| 0.3 | 版权与许可逐件登记 | 9 个语料逐件记录底本年份、藏本、来源链接、版权判定；产出清单 |
| 0.4 | 三个仓库脚手架、LICENSE 与发布身份 | `Jyutman`（MIT）/ `Jyutman-Corpus`（CC BY-SA 4.0）/ `Jyutman-Images`（CC BY-SA 4.0）建成，各自有 LICENSE 与 README；发布身份定为 GitHub 账号 huangjunxin（提交邮箱随 commit 元数据公开，站点不展示）；Cloudflare 独立账号与 Access 配置就绪 |
| 0.5 | CI 最小门禁 | GitHub Actions 跑 test + lint + typecheck + build，全绿 |

**依赖**：无（起始阶段）。

**退场条件**：0.1 若证实 trigram 方案不可行，需先定替代检索方案并更新 [01 · 愿景与范围](01-vision-and-scope.md) 的技术方向，再继续。

## Phase 1 · MVP（约 6 周）

**目标**：让 3 个已发布语料可在网上正常阅读与检索。

**依赖**：Phase 0 验收通过。

| # | 关键任务 | 验收标准 |
|---|---|---|
| 1.1 | 书目库页 | 9 个语料全部列出，标明年代、页数、状态；已发布者可点入 |
| 1.2 | 阅读器：纯文本阅读 | 分段正文、竖排/横排、校对注、缺字符号、来源信息栏；不含原书影像 |
| 1.3 | 阅读器：竖排 / 横排 | 两种排版可即时切换；手机上竖排仍可读 |
| 1.4 | 阅读器：翻页 | 页内翻页 + 跳页；URL 反映当前页 |
| 1.5 | D1 检索上线（已完成） | 汉字查询可用；结果含语料、页码、高亮片段 |
| 1.6 | 3 个语料上线（已完成） | `gd-vernacular-paper`（221 页 / 269 篇）、`canton-vernacular-handbook`（248 页 / 329 篇）、`readings-in-cantonese-colloquial`（220 页 / 268 篇）全部可读 |
| 1.7 | jyutman.com 域名接入（已完成，域名已接入） | 域名解析到 Cloudflare，HTTPS 正常，手机可访问 |

**验收标准**：在手机上完成「检索 → 开文 → 查看书目来源 → 复制引用」全流程，无阻断性问题。

## Phase 2 · 检索与阅读深化

**目标**：从「看得到」提升到「查得准、读得顺」。

**依赖**：Phase 1 验收通过。

| # | 关键任务 | 验收标准 |
|---|---|---|
| 2.1 | 繁简 / 异体归一 | 简体或异体字输入能命中原文繁体；抽样查询精确率达标 |
| 2.2 | 粤拼 ruby（已完成） | 已校对文本加注 Jyutping，以 ruby 呈现；可开关 |
| 2.3 | 历史拼式对齐 | 19 世纪传教士罗马字拼式可检索，并与现代粤拼对应 |
| 2.4 | 字典悬浮释义 | 选字可浮出释义；外连粤语辞丛、words.hk 等公开词典 |
| 2.5 | 引用导出与永久 URL | 每篇有稳定 URL；提供引用格式导出 |

**验收标准**：Phase 0 定立的检索指标（可检索率、精确率）在 3 个语料上实测达标。

## Phase 3 · 校对与开放

**目标**：让文本质量可持续提升，并让数据可被外部引用。

**依赖**：Phase 2 验收通过。

| # | 关键任务 | 验收标准 |
|---|---|---|
| 3.1 | 页级校对状态机 | `draft` / `verified` / `needs_review` 三态在 UI 如实呈现；状态传播规则与上游一致 |
| 3.2 | 众包纠错通道 | 公开提交端（POST /api/correct，Turnstile + 速率限制）＋ Cloudflare Access 保护的审阅界面（免费档 ≤50 用户，当前规模足够），採用/駁回/暫緩有记录 |
| 3.3 | GitHub Actions 回写 | 已审核的更正定时回写至数据管道，独立于站点数据 |
| 3.4 | 开放 API | 提供文章与检索的公开读取 API，有文档 |
| 3.5 | Zenodo DOI | 文本数据在 Zenodo 发布并取得 DOI |
| 3.6 | IIIF | 影像服务提供 IIIF 端点（仅限已完成版权核查的语料） |

Phase 3 分两期：3a 为公开提交端（匿名提交＋Turnstile）＋ Cloudflare Access 保护的审阅界面（免费档 ≤50 用户，当前规模足够）＋ Actions 回写；3b 视志愿者规模与权限需求再启动，为带账号体系的审阅员角色与任务流（对应 docs/02 §11 第三版）。

**验收标准**：外部贡献者能提交更正并被采纳；有外部引用出现。

## 阶段依赖链

Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4

- 每个阶段的验收标准未达成，不进入下一阶段。
- Phase 0 属「先证伪」性质：目的是在投入产品代码前推翻不成立的假设，因此有可能改写技术方向。
- Phase 2 之后的阶段不设具体时长，因为工作量取决于前期实测结果。

## 各阶段主要风险

| 阶段 | 主要风险 | 应对 |
|---|---|---|
| Phase 0 | trigram 检索方案被实测证伪 | 预留替代方案；结论写入文档再继续 |
| Phase 0 | 部分语料版权状态不明 | 不确定者暂不发布，先发可确定的部分 |
| Phase 1 | 竖排在手机上的体验 | 早期即用手机实测，不留到最后 |
| Phase 1 | 页面数估算失准，撞 Cloudflare 上限 | 上线前先估算总页数 |
| Phase 2 | 繁简异体映射表覆盖不足 | 以真实查询抽样验证，不追求一次到全量 |
| Phase 2 | 历史拼式映射工作量大 | 分期推进，先做骨架 + 抽样覆盖率 |
| Phase 3 | 众包纠错质量参差 | 提交与审核分离，回写前必经人工确认 |
| Phase 4 | AI 环节质量与成本不可控 | 不作承诺；具备条件先另行立项 |
