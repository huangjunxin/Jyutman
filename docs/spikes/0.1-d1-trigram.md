# 0.1 D1 FTS5 trigram 可行性实测（本地 + 生产 D1）

## 1. 结论摘要

1. **trigram 方案本地成立。** 在 Python 3.12.13（pyenv，/Users/trenton/.pyenv/versions/3.12.13）的 sqlite3 上，运行时 SQLite 版本 3.51.0（不低于 3.34），FTS5 已启用。对 3 个已发布语料共 866 篇、791,610 字符建 trigram 虚拟表：本组 3 字及以上查询（含中文、中英混排、罗马字）召回 100%、精确 100%，中位延迟 0.03 至 0.13 毫秒（866 行本地规模）。
2. **unicode61 确认不可用。** 中文子串召回大幅失败：「廣東」0/34，「白話報」0/16，「聖藥」0/2，「廣東白話報」0/3，「中國」1/48，「唔係」43/165（26%）。拉丁只覆盖整词，子串漏召回明显：「Cap」6/27，「LESSON」14/28。
3. **短查询（1 至 2 字）必须降级。** trigram 对 1 至 2 字查询返回 0 命中且不报错（无三元组可构造），实测确认。降级选型：2 字及以上用 bigram 辅助表（短语构造，召回与精确均 100%，0.03 至 0.26 毫秒），单字用 unigram 辅助表（100%，0.9 毫秒）；LIKE 全表扫描作为最简兜底（100%，1.1 至 1.8 毫秒，但随语料线性变慢且无法走索引）。
4. **OR 组合三元组不是原生 trigram 的正确查询构造。** 3 字及以上直接对整串做短语 MATCH 即精确匹配；OR 组合滑动三元组只得到超集（本组精度 6% 至 19%），必须再 LIKE 后过滤才能恢复精确。OR 组合只建议用于「D1 无 trigram、改用应用层 n-gram 列」的退路。
5. **生产 D1 复核已通过（2026-10-03）。** D1 上 trigram tokenizer 建表与查询均可用；五组查询召回与本地一致，2 字查询同样返回 0（短查询降级在生产同样必要），bigram 辅助表可直接工作。D1 屏蔽版本自省函数，无法读到具体版本号，以 trigram 可用推定 SQLite 不低于 3.34。详情与延迟数据见第 8 节；Worker 内延迟与计费影响待 Phase 1 实测。

## 3. 方法

### 3.1 建表与查询构造

```sql
-- 基表（只读语料，来自 data/<corpus>/articles.jsonl，每篇一行）
CREATE TABLE articles (
  id TEXT PRIMARY KEY, corpus TEXT NOT NULL, issue TEXT, page INTEGER,
  seq INTEGER, title TEXT, text TEXT NOT NULL, status TEXT
);

-- 主索引与对照索引
CREATE VIRTUAL TABLE fts_trigram   USING fts5(id UNINDEXED, title, text, tokenize='trigram');
CREATE VIRTUAL TABLE fts_unicode61 USING fts5(id UNINDEXED, title, text, tokenize='unicode61');

-- 查询：3 字及以上，整串短语 MATCH，按列限定到正文
SELECT id FROM fts_trigram WHERE fts_trigram MATCH 'text : "白話報"';

-- 查询：OR 组合滑动三元组（仅作对照与退路实验）
SELECT id FROM fts_trigram
 WHERE fts_trigram MATCH 'text : "廣東白" OR text : "東白話" OR text : "白話報"';
```

短查询降级用两张辅助表，切分在应用层完成（纯 Python），列为空格分隔的 n-gram 串，交给 unicode61 建索引：

```sql
CREATE VIRTUAL TABLE fts_bigram_aux  USING fts5(id UNINDEXED, seg, tokenize='unicode61');
CREATE VIRTUAL TABLE fts_unigram_aux USING fts5(id UNINDEXED, seg, tokenize='unicode61');

-- seg 示例：白話報係中國人嘅聖藥
--   bigram  seg：白話 話報 報係 係中 中國 國人 人嘅 嘅聖 聖藥
--   unigram seg：白 話 報 係 中 國 人 嘅 聖 藥
-- 2 字查询（精确）：
SELECT id FROM fts_bigram_aux  WHERE fts_bigram_aux  MATCH 'seg : "唔係"';
-- 1 字查询（精确）：
SELECT id FROM fts_unigram_aux WHERE fts_unigram_aux MATCH 'seg : "唔"';
-- 3 字及以上查询也可走 bigram 短语（连续位置即子串语义）：
SELECT id FROM fts_bigram_aux WHERE fts_bigram_aux MATCH 'seg : "白話 話報"';
```

切分规则：CJK 连续段内滑动取 n-gram；拉丁与数字连续段按整词保留（另在应用层三元组实验中按小写滑动三元组）。短语构造时**必须保留重复 n-gram**，不能去重，否则丢失位置语义（实测：查询「哈哈哈」用去重后的「哈哈」会误中正文「哈哈」；保留重复二元组时「哈哈 哈哈」不中「哈哈」、命中「哈哈哈」）。

### 3.2 计时与体积

每个查询先预热 3 次，再跑 20 次取中位（Python perf_counter，单位毫秒）。建表与插入分别计时（单次）。体积用 VACUUM 后的 dbstat 聚合（页大小 4096）。临时脚本与原始结果：/tmp/jm-spike/run_spike.py、/tmp/jm-spike/results.json、/tmp/jm-spike/run_console.txt（临时文件，未入库）。

## 5. 结论与选型建议

1. 主检索采用 FTS5 trigram（若 D1 可用）：3 字及以上直接整串短语 MATCH，不做 OR 展开；查询串需转义双引号并按列限定 text（生产可能同时限定 title）。
2. 2 字查询：bigram 辅助表短语查询，精确且快；LIKE 扫描可作临时或兜底方案（当前规模 866 行毫秒级；语料增长后线性变慢，D1 上还会放大读取行数，建议不作为主路径）。
3. 1 字查询：unigram 辅助表；若不建辅助表则退回 LIKE。
4. 拉丁查询：3 字及以上走 trigram（大小写折叠加子串匹配，teng、Cap、LESSON 全部 100%）；1 至 2 字的纯拉丁查询本次未测，待验证，可先走 LIKE。
5. 应用层 n-gram 列是「D1 无 trigram」时的退路：bigram 短语可精确覆盖 2 字及以上 CJK，OR 组合三元组覆盖 3 字及以上但需 LIKE 后过滤，二者结合可保留全部查询能力（见第 6 节退路小节）。
6. 繁简与异体归一（docs/02 第 6.2 节的 text_norm）不属本任务范围，本次未做。

### 6.3 若 D1 无 trigram 的退路：应用层 n-gram 预切分列

1. 首选形态（D1 支持 FTS5 但仅 unicode61）：构建期把每篇正文切成空格分隔的 n-gram 串存入 FTS5 unicode61 表，即本报告的 bigram_aux 与 unigram_aux。查询路由：2 字及以上用 bigram 短语，3 字及以上也可用「bigram 短语」或「三元组 OR + LIKE 后过滤」；1 字用 unigram。本地实测全部 100% 召回。
2. 最简形态（连 FTS5 都不可用）：普通表增加 ngram 列，查询 `ngram LIKE '% 唔係 %'`（两端补空格保证词边界）。无索引，延迟与 LIKE 同量级，仅适合小规模或临时方案（待验证）。
3. 拉丁子串：应用层三元组列 OR + LIKE 后过滤（本地 100% 召回，0.08 至 1.90 毫秒），或直接 LIKE。
4. 注意事项：保留重复 n-gram（否则位置语义错误）；切分按 CJK 连续段滑动、拉丁整词保留；预切分对 791,610 字符约 0.7 秒（纯 Python），同步脚本可接受。
