## 背景与问题

历史粤语文献面临三重困难：

1. **分散**。19 世纪传教士文献、方言报纸、读本散落于 Internet Archive、各大学图书馆特藏与私人收藏，缺少统一入口。
2. **体量可观但数字化程度低**。19 世纪传教士留下的粤语材料约有 25 种词典和 40 种教科书；目前已进入公开可检索状态的只占其中一小部分。
3. **难以阅读与引用**。即使有扫描影像，缺少文本层就无法检索、无法复制、无法引用；而竖排、三语混排、19 世纪罗马字拼式，又令通用 OCR 与阅读工具直接失效。

结果是：研究者只能逐页翻看影像，一般读者则根本无从进入。

## 读者对象

| 读者 | 主要需求 | 本站提供 |
|---|---|---|
| 语言学 / 方言学研究者 | 例句检索、历史拼式对照、可引用 | 全文检索、永久 URL、引用导出 |
| 近代史 / 传教史研究者 | 文献脉络、版本与来源信息 | 书目库、语料来源逐件登记 |
| 粤语教师与学习者 | 可读文本、注音、释义 | 竖排阅读、粤拼 ruby、字典悬浮释义 |
| 一般读者 / 粤语文化爱好者 | 看得懂、读得顺 | 面向手机友好的阅读器 |
| 开发者 / 数据使用者 | 干净、授权明确的文本 | 开放数据仓库、开放 API、DOI |

## 典型使用场景

| # | 场景 | 涉及能力 |
|---|---|---|
| S1 | 查「广东」一词在 19 世纪粤语文献中的用例 | 全文检索、繁简归一（同字简转繁） |
| S2 | 读 1907 年《广东白话报》某一期，同时查看该页来源信息 | 文本阅读、竖排阅读、来源信息展示 |
| S3 | 对比同一句话在 1874 年与 1894 年读本中的拼式差异 | 历史拼式检索、跨语料结果合并 |
| S4 | 在论文中引用某篇文章的某一段 | 永久 URL、段落级定位、引用导出 |
| S5 | 下载全部已校对文本作语料库研究 | 开放数据、DOI |

## 项目愿景

> 将 1842–1907 年间的粤语白话文献，变成一个可检索、可对照、可引用、对手机与桌面都友好的开放阅读平台。

## 目标

| # | 目标 | 具体表现 |
|---|---|---|
| G1 | 阅读体验对标识典古籍 / ctext.org | 分段阅读、竖排、校对注、来源信息展示；影像对照待版权核查后开放 |
| G2 | 检索能力覆盖多种书写系统 | 汉字检索、繁简归一（只转同一个字的简繁写法，不同的字如 嘢 / 野 不归并）、粤拼检索、历史拼式检索 |
| G3 | 数据开放可引用 | 文本与影像清单分开发布、永久 URL、可导出引用、有 DOI |
| G4 | 多端兼容 | 手机 / 平板 / 桌面均可正常阅读，无需安装任何东西 |
| G5 | 只读展示层，不回写管道 | 本站永不修改上游数据；所有更正经由独立通道回流 |

## 非目标

明确**不做**的事，避免范围蔓延：

| # | 非目标 | 理由 / 去处 |
|---|---|---|
| N1 | 不做词典内容本身 | 词典内容已有粤语辞丛等现有站点覆盖，本站不重复建设 |
| N2 | 不做 OCR 引擎研发 | OCR 由 JyutmanDataPipeline 负责；本站只消费其产出 |
| N3 | 不做付费墙 | 底本属公有领域，平台定位为开放存取 |
| N4 | 早期不做 AI 翻译 | 文白翻译 / 问答属 Phase 4 远期设想，非现阶段承诺 |
| N5 | 不做数据录入后台的完整 CMS | Phase 3 只做轻量众包纠错，非通用编辑器 |

## 项目渊源与边界

| 项目 | 提供 | 消费 | 契约 |
|---|---|---|---|
| JyutmanDataPipeline | `data/<corpus>/{articles,pages,issues}.jsonl` | （无） | 站点只读；字段见下方字段契约 |
| Jyutman（本站） | 网页阅读器、检索、书目、引用导出 | 上游 jsonl | 不回写；上游字段变更需同步更新本站入库逻辑 |
| 粤语辞丛（外部参考站点） | 粤语词典查询 | （无） | 本站可外链过去，但不复制其词典数据 |
| JyutmanDataPipeline ← 本站 | （无） | Phase 3 的 corrections 记录 | 经 GitHub Actions 回写，属独立通道，不是直接改上游文件 |

**状态契约**：`status` 取值 `draft` / `verified` / `needs_review`；页面级状态会传播到文章级，即一页内任一文章未校对，该页产出的文章状态亦受限。本站 UI 必须如实反映此状态，不得把 `draft` 呈现为已校对。

**字段契约**（摘要；完整字段语义、已知坑与本站衍生数据层见 [03 · 数据契约](03-data-contract.md)）：

| 字段 | 含义 | 本站用途 |
|---|---|---|
| `id` | 文章稳定标识 | 永久 URL 的基础 |
| `corpus` | 所属语料代号 | 书目库分组、路由 |
| `issue` | 所属期次（报刊类） | 期次导航 |
| `issue_date` | 出版日期 | 书目显示、排序 |
| `page` | 所在页码 | 影像定位、翻页 |
| `seq` | 页内序号 | 阅读顺序 |
| `source_image` | 对应扫描影像标识 | 来源信息展示；影像对照待逐件版权核查后开放 |
| `title` | 标题 | 列表与检索结果显示 |
| `text` | 正文文本 | 全文检索、阅读器正文 |
| `unclear` | 不确定字符标记 | 置信度可视化 |
| `status` | 校对状态 | 状态如实呈现 |

## 范围守则

| # | 守则 | 判断方式 |
|---|---|---|
| 1 | 只读上游 | 站点代码不得出现写入上游数据目录的路径 |
| 2 | 不重复造轮 | 遇到「这件事是否该由粤语辞丛或数据管道做」时，先停手 |
| 3 | 先证伪 | 关键技术假设未实测，不落产品代码 |
| 4 | 契约先于代码 | 字段或状态语义变更，先改本文档 |
| 5 | 不承诺未定数字 | 未实测的百分比一律标「待决策」 |

## 质量基线

识典古籍公布的 OCR 文字识别率为 96%+，可作为行业参照；但本项目的文本是三语混排加 19 世纪拼式，难度高于一般古籍，因此**不直接套用该数字**，而是建立自己的可量化基线。

建议验收指标（具体阈值待 Phase 0 用真实语料实测后确定）：

| 指标 | 定义 | 建议目标 | 状态 |
|---|---|---|---|
| `verified` 页面占比 | 已人工校对页 / 已发布页 | 首发 3 语料达 30% 以上 | 待决策 |
| 可检索率 | 能被 FTS5 正确切分并命中的页面占比 | 95% 以上 | 待决策 |
| 检索精确率 | 抽样查询中首屏命中相关页的比例 | 90% 以上 | 待决策 |
| `unclear` 标记密度 | 每千字符的不确定字符数 | 逐语料登记基线，不设硬性上限 | 待决策 |
| 首屏可用时间 | 手机 4G 下首次可读 | 3 秒内 | 待决策 |
| 影像对照定位准确率（仅限已开放影像的语料） | 点击文本段落能定位到正确影像区域 | 98% 以上 | 待决策 |

量测方法（细节待 Phase 0 确定）：

| 项目 | 做法 |
|---|---|
| 抽样方式 | 每个语料随机抽固定页数人工核对；同一页由两人各核一次 |
| 量测频率 | 每个里程碑量测一次，结果记入验收记录 |
| 记录去向 | 计数与抽样明细并入 `Jyutman-Corpus` 的验收记录 |
| 对照基准 | 不对外横向比较；只与自己上一版比，确认无退步 |

## 成功标准

短期（Phase 1 完成）：

- 3 个已发布语料（`gd-vernacular-paper` / `canton-vernacular-handbook` / `readings-in-cantonese-colloquial`，ID 前缀 `gdvp` / `cvh` / `rcc`；合计 689 页 / 866 篇）全部可读、可检索。
- 手机上能顺畅完成「检索 → 开文 → 查看书目来源 → 复制引用」全流程。
- jyutman.com 对外可访问。

中期（Phase 3 完成）：

- 有外部研究者引用本站永久 URL。
- 有外部贡献者通过纠错通道提交更正。
- 文本数据有可引用的 DOI。

长期（持续观察）：

| # | 标准 | 观察方式 |
|---|---|---|
| L1 | 检索结果被实际使用，不止首页浏览 | 由检索到开文的转化情况 |
| L2 | 文本数据被外部取用 | `Jyutman-Corpus` 的下载与引用记录 |
| L3 | 有站外链接指向具体文章 URL | 反向链接抽样 |

**明确不算成功**：页面数增加但文本质量无提升；或站点可用但无人引用、无人取用数据。

## 主要风险

| # | 风险 | 影响 | 缓解方向 |
|---|---|---|---|
| R1 | 影像版权状态逐件不同 | 未经核查公开影像有法律风险 | 影像预设不公开；仅完成藏馆条款核查的语料逐件开放 |
| R2 | D1 FTS5 trigram 未实测 | 检索方案可能不成立，需要换方案 | Phase 0 做可行性实测，用真实语料量测召回与延迟 |
| R3 | Cloudflare 静态文件数上限 | 页面数膨胀后可能撞上限 | 估算页面数；必要时改为按需渲染或分片部署 |
| R4 | 历史拼式映射工作量大 | 历史拼式检索迟迟做不到 | 先做映射表骨架 + 抽样覆盖率，非全量 |
| R5 | 生僻字字体体积大 | 首屏拖慢，尤其是手机 | 字体子集化 / 按需加载 / 系统字体回退 |
| R6 | 上游字段或状态语义变更 | 本站入库逻辑失效 | 契约写死在本文档；上游变更需同步更新本站 |

## 贡献约定

| 约定 | 内容 |
|---|---|
| 文档单一事实源 | 文档与实现必须一致；如脱节，以代码为准并及时修正文档 |
| 范围变更 | 任何非目标或契约变更，先更新本文档再落代码 |
| 数据边界 | 站点不改上游数据；所有更正走独立通道 |
